# Online Play Implementation Plan (Plan 5 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play a friend on another device: create a match, share a 6-char code, play a full match with server-authoritative dice, resilient turn sync, and the same board/tutor UX — built and verified entirely against the local Firebase Emulator Suite (production deploy is a documented, user-run step).

**Architecture (key decisions — read before any task):**
1. **The Firestore event log IS the game** (spec §4). `/matches/{id}` doc (players, seats, code, status, matchLength, scores) + `events` subcollection (ordered `seq` ints, each a core `GameEvent.toJson()` + game number). Clients FOLD the ordered stream into `Game`/`MatchState` locally (validating every event via `Game.append` — an illegal event = divergence = full refetch) and only SUBMIT their own decisions. This inverts Plan 3's local loop — a new `OnlineMatchController` handles it; the local `GameController` is untouched.
2. **Pure-Dart Firestore REST transport — NO FlutterFire plugins.** cloud_firestore has no Windows desktop support and needs console-generated config; the REST API works everywhere (desktop dev, CI, emulator) and needs only projectId + API key (emulator: no key). Realtime push is replaced by bounded POLLING (2s while the online screen is open) — fine for turn-based play; a FlutterFire realtime upgrade is recorded as deferred.
3. **Server-authoritative dice** via Cloud Functions (`rollDice`, plus `createMatch`/`joinMatch` for atomic seat claiming and code allocation). Clients NEVER write Roll/OpeningRoll events; functions do, transactionally, after validating the caller holds the on-turn seat. Security rules enforce: participants-only reads, append-only events, correct `seq`, event author == seat uid, no client-written roll events, no doc mutation outside functions (scores/status updated by functions? v1: clients may NOT update the match doc at all except via functions — functions handle join; game/match completion status is derived client-side and finalized by the `finalizeGame` function? SIMPLER v1: a `submitEvent` callable validates + appends ALL client events server-side (turn + seat + seq + type whitelist), so rules only need "clients read own matches, write NOTHING". One function path = far smaller rules surface. DECIDED: all writes go through callables; Firestore rules = read-only for participants.)
4. **Auth:** Firebase anonymous auth via Identity Toolkit REST (`accounts:signUp`). Emulator accepts any API key; production needs the project's Web API key — a user-supplied config value (`OnlineConfig`), absent → online UI shows "not configured".
5. **Toolchain:** Node LTS + `firebase-tools` (npm -g), Java 25 already present. All emulator tests run under `firebase emulators:exec` with a `demo-aigammon` project id (fully offline, no credentials).

**Structure:** new pure-Dart package `packages/online_client` (REST transport + auth + match API, emulator-tagged tests); `firebase/` dir (firestore.rules, functions/ TypeScript, firebase.json); app gains `app/lib/online/` (OnlineMatchController) + screens; `MatchController` interface extracted so GameScreen serves both local and online controllers.

**Environment:** Windows dev box; PATH refresh incantation for all tools: `$env:Path = [System.Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [System.Environment]::GetEnvironmentVariable('Path','User')`. Suites at start: core 107, bindings 28+17, app 134+E2E.

### Task 2: Cloud Functions (TypeScript)
`firebase/functions/`: `createMatch({matchLength})` → allocates unique 6-char code (A-Z2-9, retry on collision), creates match doc {code, matchLength, status:'waiting', uids:[caller], seats:{white:caller}, scores 0-0, createdAt}, returns {matchId, code}; `joinMatch({code})` → transactional seat claim (status waiting → active, seats.black=caller, uids append; errors: not found/full/own match), then appends the game-1 `openingRoll` event (server dice, re-roll ties) with seq 0; `rollDice({matchId})` → validates caller seat == folded on-turn player and phase awaitingRoll (folding: functions keep a LIGHT server-side check — full rules live in the client; server validates: it's the caller's seat's turn per a `turn` field maintained on the match doc by every append — DECIDED: functions maintain `turn`+`phase`+`gameNo`+`seq` summary fields on the match doc on every event append, computed with a MINIMAL TS mirror of turn-flow (not full move legality — moves are validated by both clients via backgammon_core; a cheater's illegal move is rejected by the opponent's client as divergence, recorded limitation v1)); `submitEvent({matchId, event})` → whitelist (move/double/take/drop/resignOffer/resignAccept/resignDecline), author check (event.player == caller's seat), turn check, seq assignment, appends + updates summary; on gameOver-detection… v1: when a client detects game end it calls `finalizeGame({matchId, result})` and the function cross-checks BOTH clients agree? Simpler v1: `submitEvent` also accepts a `result` claim with the terminal event; function stores scores/status ('complete' when match done) trusting the SUBMITTING client + opponent-divergence as the audit (recorded v1 trust model). Jest not required: functions tested in Task 4 via the emulator from Dart. `npm run build` must pass (tsc strict). Commit.

Unit tests: URL/envelope construction with a mock http client (no emulator needed — NOT tagged). Commit.

### Task 6: OnlineMatchController
`app/lib/online/online_match_controller.dart` implements MatchController over `MatchApi`: folds polled events (validating each via Game.append; on StateError → divergence recovery: refetch all events, rebuild, surface a transient notice), submits local decisions (submitEvent/rollDice), maintains MatchState from summary+results, exposes the interaction surface for the local seat, disposes cleanly (stop polling). Offline resilience: submit failures retry once then surface error (banner) without corrupting local fold. Tests with a FakeMatchApi (scripted event streams): full match fold, out-of-order/duplicate seq tolerance (ignore seen seq), divergence recovery path, submit-retry, dispose-stops-polling. Commit.
