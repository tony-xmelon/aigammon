**Goal:** "need to add a way to play with two nearby devices as well" — two phones on the same Wi-Fi play a match with no internet/Firebase dependency.

**Architecture:** Reuse the event-log-as-truth + `MatchController` duality that online play proved out. The HOST device is the authority (it has the full rules engine): it owns the authoritative `Game`/`MatchState`, rolls dice, validates the guest's submissions, and broadcasts a seq-numbered event log over a WebSocket it serves on the local network. The GUEST folds the stream exactly like `OnlineMatchController` folds Firestore events. Discovery: UDP broadcast probe (guest) + beacon responder (host), with manual IP:port entry as the always-available fallback (iOS multicast entitlements make UDP discovery Android-first; document).

**Trust model:** identical to online v1 — host-authoritative dice and validation; the guest trusts the host. Two friends in a room; acceptable.

**Tech:** pure `dart:io` (HttpServer WebSocket upgrade, RawDatagramSocket for discovery) — no new plugins except `network_info_plus` (host's Wi-Fi IP display). New package `packages/lan_play` (pure Dart, fully unit-testable in-memory).

---

### Task 1: Protocol + host authority (packages/lan_play)
- `protocol.dart`: JSON message envelope {type, seq?, payload} — types: `hello` (guest→host: protocol version, display name), `welcome` (host→guest: match config, assigned side, full event log), `event` (host→guest: seq-numbered GameEvent JSON — REUSE backgammon_core's event JSON codec), `submit` (guest→host: intended event for their turn), `reject` (host→guest: reason + resync log), `roll_request` (guest→host), `ping/pong`. Version field; unknown types ignored.
- `host_authority.dart`: owns `MatchState`/`Game` (backgammon_core), a `DiceRoller` (Random.secure), the append-only log with seqs; mirrors firebase/functions turnflow rules IN DART: validates the submitter's turn/side/legality (full `legalMoves` check — stronger than the server v1!), applies, appends, broadcasts; handles game/match completion, next-game, cube, resign. Pure — transport-agnostic (in/out message sinks).
- Tests: authority happy-path full game (scripted dice via injectable roller); rejection cases (out of turn, illegal move, wrong side, stale seq); JSON round-trips; version mismatch.

### Task 2: Sockets — host server + guest client (packages/lan_play)
- `host_server.dart`: `HttpServer.bind(anyIPv4, port)` + WebSocket upgrade at `/match`; single-guest policy (second connection → busy); wires socket ↔ HostAuthority; heartbeat ping 5s, drop on 15s silence; graceful re-join (guest reconnects → `hello` with resume token → full log replay).
- `guest_client.dart`: connect, hello/welcome handshake, event stream out, submit in; auto-reconnect with backoff while the screen is open.
- Tests: in-memory loopback (bind port 0) host+guest pair: handshake, event flow, reconnection replays log, busy rejection, heartbeat drop.

### Task 3: LanMatchController (app)
- `app/lib/lan/lan_match_controller.dart` implements `MatchController` (study `OnlineMatchController` — reuse the seq-contiguous folding, AppliedMove lastMove contract, divergence-refetch-on-gap via full-log request, persistence hooks, `cubeless` from host config). Host side ALSO plays through a controller: `LanMatchController.host(...)` wraps the local authority directly (no socket loop for the host's own actions — in-process sink pair).
- Tests: fake transport pair driving both controllers through a scripted game incl. reconnect mid-game; game_screen smoke with the controller.

### Task 4: Discovery + UI (app)
- `discovery.dart` (lan_play): host beacon — RawDatagramSocket on udp/47777 answering `AIGAMMON?v1` probes with `{name, port}` and nothing more; guest prober — broadcast + collect responses 2s. **The room code is NEVER broadcast** (the answer carries a constant `code: false`, advertising only that a code is required): it is the one thing standing between a stranger on the Wi-Fi and the match, so putting it in a broadcast reply would hand it to exactly the people it excludes. The host's **address is likewise never self-reported** — the guest takes it from the observed source of the reply datagram, so a host cannot point probers at a third party. Android-first; iOS falls back to manual entry (document the entitlement path in native/README.md for later).
- UI: home gains "Play Nearby" → `lan_screen.dart`: HOST tab (match length/cubeless selectors → "Start hosting" → shows big room code + IP:port + waiting spinner → auto-enters GameScreen on guest join) / JOIN tab (discovered hosts list auto-refreshing + manual IP:port field + room code entry → join → GameScreen). Reuse new_match_screen idioms. Errors surfaced clearly (wrong code, host gone, version mismatch).
- Permissions: Android INTERNET (present); verify no extra manifest needs for UDP broadcast receive. `network_info_plus` for the host IP display.
- Tests: widget tests for both tabs (fake discovery/transport); host-flow and join-flow reach GameScreen.

### Task 5: Two-controller integration test
- In-process host+guest over real loopback sockets playing a full scripted game to completion incl. a resign and a reconnect; both persistence hooks record; both screens' state converges (drive controllers directly, not widgets, for determinism).

### Task 5.5 (added from live feedback): tabletop hot-seat
Verbatim: "when playing person vs person, the default should be not flipping the board. People will share the device at each side, place action buttons for each player, and keep the board fixed".
- Hot-seat DEFAULT: board orientation FIXED for the whole match (no flip between turns). The two players sit at opposite edges of the device.
- Each player acts from their OWN edge: the bottom player keeps the current bottom action bar; the TOP player gets a mirrored action bar at the top edge, ROTATED 180° (RotatedBox) so it reads right-side-up for them — shown/enabled only on their turn (fixed height always, F6). Same for the per-turn affordances that matter mid-turn (Roll/Confirm/Undo; hint if tutor on). The header/score sheet stay bottom-reader-oriented (the "owner" of the device) — do NOT rotate the whole UI; only the top player's action bar + their dice-tap affordance need to work from their side.
- The board-flip behavior remains available as a setting ("Rotate board between turns", default OFF; replaces/renames the existing followActive wiring for hot-seat) — schema change only if a new column is genuinely needed (check: orientation may already be a runtime option; persist under a new settings column extending the current schema version if unshipped, else bump).
- The pass-device overlay stays available (independent setting, already default-off).
- Tests: fixed orientation across turns by default; top bar rotated and functional (tap Roll/Confirm from top player's turn); flip setting restores old behavior; F6 heights stable.
